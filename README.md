Insurance agency management CRM foundation built with React, TypeScript, and Vite.

## Scripts

```bash
npm install
npm run dev
npm run build
```

## Current foundation

- Agency dashboard shell with sidebar navigation and top search.
- Agency Command Center dashboard with active clients, renewals due, open tasks, quotes pending, active policies, and monthly premium cards.
- Customizable dashboard widgets for communications, upcoming renewals, today's follow-ups, recent client activity, and key accounts.
- Clients page with search, New Client placeholder, filters, and a QuickFile-style client list/table.
- Client profile/folder is the primary workspace and opens by default.
- Sidebar is focused on Dashboard, Clients, Leads, Reports, and Administration.
- Lead hub for new website quote requests, referrals, walk-ins, and prospects before they become client folders.
- Client profile/folder page with overview, contact info, expandable policies, policy-level billing/payment details, memos, tasks, communications, forms, and activity tabs.
- Responsive layout for desktop and mobile.
- Account/user scoped CRM storage using browser localStorage as the first development layer.
- Typed CRM records for agency accounts, users, clients, policies, renewals, tasks, and opportunities.
- AgencyIQ Glow is the default appearance theme, and user-selected themes are remembered locally.
- Role-based owner analytics visibility: Agent/Owner, Principal Agent, and Admin can see company-level revenue/book analytics; CSR and Producer views keep operational CRM access while hiding owner-only analytics.
- Owner-only sales reports for new business written premium, renewal premium retention, missed sale review, and incomplete follow-up/task analytics, including per-user breakdowns.
- Realistic demo data for 8 clients, mixed personal/commercial files, multiple policies, premiums, commission values, notes, tasks, and upcoming renewals.
- New Client, widget persistence, form creation, and ACORD workflows are placeholder UI for later backend/build phases.

## Next build areas

- Real navigation and page routing.
- Authentication and user roles.
- Backend API and database integration.
- Move the current scoped localStorage data layer into the backend database.
- Enforce role permissions on the backend, not only in the frontend UI.
- Dedicated client files, notes, reminders, renewal workflows, and future document storage.
